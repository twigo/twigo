# Credentials: exec plugins, sign-in and the oidc provider

Research of 2026-11-01 for M1 step 4, before Twigo got credentials itself.
It read client-go at v1.37.2, kube-rs at 4.2.0, the exec plugins at their latest releases, and the Kubernetes clients and OIDC issuers named below at their tags.
The design it led to is in [ARCHITECTURE](../ARCHITECTURE.md) 6.2.

## What client-go does with an exec plugin

- **The plugin gets the process environment, then the entry's `env`, then `KUBERNETES_EXEC_INFO`**, the last of each name winning ([exec.go at v1.37.2](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L450-L455)).
  stdin is passed only when the plugin is interactive, else it reads `/dev/null`; stderr goes to the terminal, stdout into an unbounded buffer, and nothing times the run ([L457-L472](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L457-L472)).
- **`interactiveMode`** decides `spec.interactive`: `Never` and, without a terminal, `IfAvailable` give false; `Always` without a terminal refuses with `exec plugin cannot support interactive mode: standard input is not a terminal` ([L234-L259](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L234-L259)).
  v1beta1 defaults the mode to `IfAvailable`, and v1 requires it ([validation.go](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/tools/clientcmd/validation.go#L323-L330)).
- **`spec.cluster`** goes to the plugin only with `provideClusterInfo`: server, TLS server name, the CA's bytes, `proxy-url`, `disable-compression` and the cluster extension `client.authentication.k8s.io/exec` as `config` ([rest/exec.go](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/rest/exec.go#L31-L61)).
- **One authenticator per exec config and cluster info, for the whole process**, so contexts that name the same plugin share one run and one token ([exec.go L71-L120](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L71-L120)).
  A credential counts as expired only once its `expirationTimestamp` passes; without one it lasts until a 401 ([L387-L392](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L387-L392)).
  One mutex covers the cache and the run, with no timeout and no memory of a failure, so a failing plugin runs again on the next request ([L402-L415](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L402-L415)).
- **A 401 refreshes for the next request**, if the request's credential is still the cached one, and returns the 401 ([L367-L384](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L367-L384), [L419-L431](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L419-L431)).
- **A client certificate goes in at each handshake**, and a new one closes every connection the old one opened ([L328-L331](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L328-L331), [L525-L535](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L525-L535)).
- **The output** must carry the configured apiVersion (v1 or v1beta1) and a `status` with a token, a PEM certificate and key, or both; JSON or YAML, unknown fields ignored ([L478-L495](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L478-L495)).
- **A token, basic auth or a client certificate in the entry wins**, and the plugin never runs ([L314-L322](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/exec/exec.go#L314-L322)).
- **The gcp and azure auth providers are removed**: client-go keeps stubs that fail with a pointer to `gke-gcloud-auth-plugin` and Azure/kubelogin ([gcp_stub.go](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/gcp/gcp_stub.go#L26-L36), [azure_stub.go](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/client-go/plugin/pkg/client/auth/azure/azure_stub.go#L26-L36)).

## Why kube-rs's exec auth does not fit

- kube-client 4.2.0 runs the plugin with a blocking `Command::output` from `Auth::try_from`, three times for each `Client::try_from` and four with an https proxy, and again in `spawn_blocking` to refresh, with no timeout ([auth/mod.rs](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/auth/mod.rs#L568-L643), [builder.rs](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/builder.rs#L164-L217)).
- It inherits the terminal's stdin and stderr unless the mode is `Never`, and sends `interactive: true` for `IfAvailable` ([mod.rs L587-L598](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/auth/mod.rs#L587-L598)).
- It bakes a plugin's certificate into a fixed rustls config ([tls.rs](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/tls.rs#L90-L96)).
- `auth-provider: gcp` with `cmd-path` runs a blocking command in the same places ([mod.rs L440-L454](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/auth/mod.rs#L440-L454)).
- Every request body kube builds holds its bytes, so one retry can rebuild it with `Body::try_clone`, taken before the body is sent ([body.rs](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/body.rs#L57-L95)).

## How the plugins sign in

- **`interactiveMode` says nothing**: int128/kubelogin documents `Never` for a flow that opens a browser ([README at v1.36.4](https://github.com/int128/kubelogin/blob/v1.36.4/README.md#L40-L52)), and Azure/kubelogin, pinniped, tsh and aws leave it out.
  No plugin read reads `spec.interactive`.
- **A warm cache answers at once and silently** for every plugin read, but none can be told to fail rather than prompt.
  Azure/kubelogin falls through to the device code or the browser by itself ([azidentity public_client.go](https://github.com/Azure/azure-sdk-for-go/blob/sdk/azidentity/v1.14.0/sdk/azidentity/public_client.go#L147-L154)).
- **Never asks:** `aws eks get-token`, which on an expired SSO session fails with `aws: [ERROR]: … run aws sso login …` (exit 255, aws-cli 2.39.3), aws-iam-authenticator, gke-gcloud-auth-plugin, doctl without SSO, `oci ce cluster generate-token`, `pinniped login static`, and Azure/kubelogin's `spn`, `msi`, `workloadidentity`, `azurepipelines`, `ropc`, `azurecli` and `azd` logins.
- **Azure/kubelogin's login method** defaults to `devicecode`, and `AAD_LOGIN_METHOD` overrides `--login` unless `--disable-environment-override` is given ([options.go at v0.2.22](https://github.com/Azure/kubelogin/blob/v0.2.22/pkg/internal/token/options.go#L88-L105), [L251-L253](https://github.com/Azure/kubelogin/blob/v0.2.22/pkg/internal/token/options.go#L251-L253)).
  Both projects ship a `kubelogin`; int128's takes `--oidc-issuer-url`.
- **A browser flow often prints nothing**: Azure/kubelogin's `interactive` never prints its URL ([MSAL public.go at v1.7.2](https://github.com/AzureAD/microsoft-authentication-library-for-go/blob/v1.7.2/apps/public/public.go#L751-L772)), and int128/kubelogin prints one only when the browser fails to open.
  The device code comes as one line of the server's own text from Azure/kubelogin ([devicecodecredential.go](https://github.com/Azure/kubelogin/blob/v0.2.22/pkg/internal/token/devicecodecredential.go#L45-L48)); its English wording was not verified.
- **Their own limits**: Azure/kubelogin gives the whole run 60 s ([options.go L136-L137](https://github.com/Azure/kubelogin/blob/v0.2.22/pkg/internal/token/options.go#L136-L137)), int128/kubelogin's browser flow 180 s ([cmd.go](https://github.com/int128/kubelogin/blob/v1.36.4/pkg/cmd/cmd.go#L28)), and tsh's SSO callback 180 s ([defaults.go at v18.10.0](https://github.com/gravitational/teleport/blob/v18.10.0/lib/defaults/defaults.go#L286-L288)).
  A tsh killed during its relogin leaves `kube_credentials.lock` behind, and every later run fails with `Having problems with relogin, please use 'tsh login/tsh kube login' manually` until a `tsh login`.
- **One run at a time**: int128/kubelogin holds a blocking file lock for its whole login ([get_token.go](https://github.com/int128/kubelogin/blob/v1.36.4/pkg/usecases/credentialplugin/get_token.go#L69-L79)), and parallel runs would open browser after browser.
- **Some flows need a terminal**: int128/kubelogin's `authcode-keyboard` and password grants, pinniped's `cli_password`, tsh's local users and an aws profile with `mfa_serial`; with no input they fail at once.

## What clients do with `auth-provider: oidc`

| Client (tag)                                      | Writes refreshed tokens back?                                                                                                                                                                                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| kubectl, client-go v1.37.2                        | yes, rewriting the user's whole file under `<file>.lock` ([config.go](https://github.com/kubernetes/client-go/blob/v0.37.2/tools/clientcmd/config.go#L165-L177), [oidc.go](https://github.com/kubernetes/client-go/blob/v0.37.2/plugin/pkg/client/auth/oidc/oidc.go#L275-L287)) |
| k9s v0.51.0, Freelens v2.0.0                      | yes, through client-go's loader                                                                                                                                                                                                                                                 |
| Python client v37.0.1                             | yes, with `yaml.safe_dump`, no lock, comments lost                                                                                                                                                                                                                              |
| Headlamp v0.46.0, `@kubernetes/client-node` 2.0.1 | no, in memory only                                                                                                                                                                                                                                                              |
| kube-rs 4.2.0, feature `oidc`                     | no; it also needs a client secret and an id-token, and ignores the IdP's CA ([oidc.rs](https://github.com/kube-rs/kube/blob/4.2.0/kube-client/src/client/auth/oidc.rs#L201-L337))                                                                                               |

- **Dex rotates the refresh token on every refresh by default**, with no reuse window, and rejects the old one ([refresh_strategy.go at v2.46.1](https://github.com/dexidp/dex/blob/v2.46.1/server/tokens/refresh_strategy.go#L58-L107)); Okta rotates for SPAs, and Keycloak only when configured.
  So a refresh kept in memory leaves kubectl a spent token; [kubie#62](https://github.com/kubie-org/kubie/issues/62) and [Headlamp #6793](https://github.com/kubernetes-sigs/headlamp/issues/6793) are that failure.
- **client-go persists before it uses the new tokens**, and drops them when the write fails, which loses the only valid refresh token ([oidc.go](https://github.com/kubernetes/client-go/blob/v0.37.2/plugin/pkg/client/auth/oidc/oidc.go#L275-L287)).
  Its lock is `O_CREATE|O_EXCL` on `<file>.lock` with no wait, and its write is in place ([loader.go](https://github.com/kubernetes/client-go/blob/v0.37.2/tools/clientcmd/loader.go#L454-L497)).
- **`yaml-edit` 0.3.6 edits a scalar without touching the rest of the file**: in a test on block and flow mappings, a missing key, a `>-` scalar, CRLF and non-ASCII comments, the diff held only the changed lines; a byte-range replacement over serde-saphyr spans corrupted the `>-` scalar.
